# RFC-001: Core Data Model

**Date:** 2025-11-10
**Status:** Accepted
**Author:** Kostiantyn Amurov
**Reviewers:** Product team

---

## Summary

This RFC defines the core relational schema for InterviewFlow. It covers the 10 primary domain entities, their relationships, key column decisions, and indexing strategy. The goal is to establish a stable foundation before MVP migrations are written.

---

## Entities and Schema

### `companies`

Represents an employer using the platform. All data is scoped to a company.

```sql
CREATE TABLE companies (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name            VARCHAR(255) NOT NULL,
  slug            VARCHAR(100) NOT NULL UNIQUE,
  domain          VARCHAR(255),                        -- e.g. "acme.com" for SSO matching
  plan            VARCHAR(50) NOT NULL DEFAULT 'trial', -- trial, starter, growth, enterprise
  seats_limit     INTEGER NOT NULL DEFAULT 5,
  logo_url        TEXT,
  settings        JSONB NOT NULL DEFAULT '{}',         -- feature flags, branding
  deleted_at      TIMESTAMPTZ,
  inserted_at     TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_companies_slug ON companies (slug);
CREATE INDEX idx_companies_deleted_at ON companies (deleted_at) WHERE deleted_at IS NULL;
```

### `users`

Platform users (recruiters, interviewers, admins) — not candidates.

```sql
CREATE TABLE users (
  id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  company_id          UUID NOT NULL REFERENCES companies(id),
  email               VARCHAR(255) NOT NULL UNIQUE,
  email_encrypted     BYTEA,                           -- AES-256-GCM encrypted copy for PII compliance
  hashed_password     VARCHAR(255) NOT NULL,
  full_name           VARCHAR(255) NOT NULL,
  avatar_url          TEXT,
  role                VARCHAR(50) NOT NULL DEFAULT 'recruiter',
                      -- admin | recruiter | interviewer | stakeholder
  confirmed_at        TIMESTAMPTZ,
  last_sign_in_at     TIMESTAMPTZ,
  deactivated_at      TIMESTAMPTZ,
  inserted_at         TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at          TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_users_company_id ON users (company_id);
CREATE INDEX idx_users_email ON users (email);
```

### `jobs`

A job posting (requisition) belonging to a company.

```sql
CREATE TABLE jobs (
  id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  company_id          UUID NOT NULL REFERENCES companies(id),
  created_by_id       UUID NOT NULL REFERENCES users(id),
  title               VARCHAR(255) NOT NULL,
  department          VARCHAR(255),
  location            VARCHAR(255),
  remote_policy       VARCHAR(50) NOT NULL DEFAULT 'hybrid',
                      -- onsite | hybrid | remote
  employment_type     VARCHAR(50) NOT NULL DEFAULT 'full_time',
                      -- full_time | part_time | contract | internship
  description         TEXT,
  requirements        TEXT,
  salary_min          INTEGER,                         -- cents
  salary_max          INTEGER,                         -- cents
  salary_currency     CHAR(3) NOT NULL DEFAULT 'USD',
  pipeline_stages     JSONB NOT NULL DEFAULT '["applied","screen","interview","offer","hired"]',
  scoring_rubric      JSONB NOT NULL DEFAULT '{}',     -- per-job AI scoring weights
  status              VARCHAR(50) NOT NULL DEFAULT 'draft',
                      -- draft | open | paused | closed | archived
  published_at        TIMESTAMPTZ,
  closed_at           TIMESTAMPTZ,
  deleted_at          TIMESTAMPTZ,
  search_vector       TSVECTOR GENERATED ALWAYS AS (
                        to_tsvector('english', coalesce(title, '') || ' ' || coalesce(department, ''))
                      ) STORED,
  inserted_at         TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at          TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_jobs_company_id ON jobs (company_id);
CREATE INDEX idx_jobs_status ON jobs (status);
CREATE INDEX idx_jobs_search ON jobs USING GIN (search_vector);
CREATE INDEX idx_jobs_deleted_at ON jobs (deleted_at) WHERE deleted_at IS NULL;
```

### `candidates`

A person applying for jobs. A candidate record is company-scoped (not global) to prevent data leakage between companies.

```sql
CREATE TABLE candidates (
  id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  company_id          UUID NOT NULL REFERENCES companies(id),
  email               VARCHAR(255) NOT NULL,
  email_encrypted     BYTEA NOT NULL,                  -- always store PII encrypted
  full_name           VARCHAR(255) NOT NULL,
  phone               VARCHAR(50),
  phone_encrypted     BYTEA,
  linkedin_url        TEXT,
  github_url          TEXT,
  portfolio_url       TEXT,
  resume_url          TEXT,                            -- Cloud Storage signed URL
  resume_text         TEXT,                            -- extracted text for full-text search
  tags                TEXT[] NOT NULL DEFAULT '{}',
  source              VARCHAR(100),                    -- linkedin | referral | careers_page | agency
  notes               TEXT,
  search_vector       TSVECTOR GENERATED ALWAYS AS (
                        to_tsvector('english',
                          coalesce(full_name, '') || ' ' ||
                          coalesce(resume_text, '') || ' ' ||
                          coalesce(notes, ''))
                      ) STORED,
  deleted_at          TIMESTAMPTZ,
  inserted_at         TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),

  UNIQUE (company_id, email)
);

CREATE INDEX idx_candidates_company_id ON candidates (company_id);
CREATE INDEX idx_candidates_search ON candidates USING GIN (search_vector);
CREATE INDEX idx_candidates_tags ON candidates USING GIN (tags);
```

### `applications`

Connects a candidate to a specific job. One candidate can have at most one active application per job.

```sql
CREATE TABLE applications (
  id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  job_id              UUID NOT NULL REFERENCES jobs(id),
  candidate_id        UUID NOT NULL REFERENCES candidates(id),
  assigned_to_id      UUID REFERENCES users(id),       -- recruiter owner
  pipeline_stage      VARCHAR(100) NOT NULL DEFAULT 'applied',
  rejection_reason    VARCHAR(255),
  cover_letter        TEXT,
  referral_name       VARCHAR(255),
  source_details      JSONB NOT NULL DEFAULT '{}',
  composite_score     NUMERIC(4,2),                    -- 0.00–10.00, updated by AI scoring
  rank_within_job     INTEGER,                         -- recomputed on each scoring update
  status              VARCHAR(50) NOT NULL DEFAULT 'active',
                      -- active | rejected | withdrawn | hired
  applied_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  stage_changed_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  inserted_at         TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),

  UNIQUE (job_id, candidate_id)
);

CREATE INDEX idx_applications_job_id ON applications (job_id);
CREATE INDEX idx_applications_candidate_id ON applications (candidate_id);
CREATE INDEX idx_applications_stage ON applications (pipeline_stage);
CREATE INDEX idx_applications_composite_score ON applications (composite_score DESC NULLS LAST);
```

### `interviews`

A scheduled interview event linking an application to one or more interviewers.

```sql
CREATE TABLE interviews (
  id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  application_id      UUID NOT NULL REFERENCES applications(id),
  scheduled_by_id     UUID NOT NULL REFERENCES users(id),
  title               VARCHAR(255) NOT NULL,
  interview_type      VARCHAR(50) NOT NULL DEFAULT 'video',
                      -- video | phone | onsite | technical | panel
  scheduled_at        TIMESTAMPTZ NOT NULL,
  duration_minutes    INTEGER NOT NULL DEFAULT 60,
  timezone            VARCHAR(100) NOT NULL DEFAULT 'UTC',
  calendar_event_id   VARCHAR(255),                    -- Google Calendar / Outlook event ID
  meeting_link        TEXT,                            -- fallback for non-WebRTC interviews
  instructions        TEXT,                            -- sent to candidate in calendar invite
  status              VARCHAR(50) NOT NULL DEFAULT 'scheduled',
                      -- scheduled | in_progress | completed | cancelled | no_show
  cancelled_reason    TEXT,
  completed_at        TIMESTAMPTZ,
  inserted_at         TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at          TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_interviews_application_id ON interviews (application_id);
CREATE INDEX idx_interviews_scheduled_at ON interviews (scheduled_at);
CREATE INDEX idx_interviews_status ON interviews (status);
```

### `interview_interviewers`

Many-to-many join: which users are conducting a given interview.

```sql
CREATE TABLE interview_interviewers (
  interview_id        UUID NOT NULL REFERENCES interviews(id) ON DELETE CASCADE,
  user_id             UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  role                VARCHAR(50) NOT NULL DEFAULT 'interviewer',
                      -- lead | interviewer | shadow | observer
  inserted_at         TIMESTAMPTZ NOT NULL DEFAULT NOW(),

  PRIMARY KEY (interview_id, user_id)
);
```

### `video_sessions`

A WebRTC session associated with an interview. An interview may have at most one active session at a time but may have multiple sessions over its lifetime (reconnects).

```sql
CREATE TABLE video_sessions (
  id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  interview_id        UUID NOT NULL REFERENCES interviews(id),
  session_token       VARCHAR(255) NOT NULL UNIQUE,    -- signed token for Channel auth
  status              VARCHAR(50) NOT NULL DEFAULT 'waiting',
                      -- waiting | active | ended | failed
  started_at          TIMESTAMPTZ,
  ended_at            TIMESTAMPTZ,
  duration_seconds    INTEGER,
  recording_url       TEXT,                            -- Cloud Storage object path
  transcript_url      TEXT,                            -- Cloud Storage path to transcript JSON
  participant_count   INTEGER NOT NULL DEFAULT 0,
  metadata            JSONB NOT NULL DEFAULT '{}',     -- browser info, network stats
  inserted_at         TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at          TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_video_sessions_interview_id ON video_sessions (interview_id);
CREATE INDEX idx_video_sessions_token ON video_sessions (session_token);
CREATE INDEX idx_video_sessions_status ON video_sessions (status);
```

### `coding_challenges`

A coding problem attached to a job or interview.

```sql
CREATE TABLE coding_challenges (
  id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  company_id          UUID NOT NULL REFERENCES companies(id),
  job_id              UUID REFERENCES jobs(id),        -- NULL = company library challenge
  created_by_id       UUID NOT NULL REFERENCES users(id),
  title               VARCHAR(255) NOT NULL,
  description         TEXT NOT NULL,                   -- Markdown with problem statement
  difficulty          VARCHAR(50) NOT NULL DEFAULT 'medium',
                      -- easy | medium | hard
  allowed_languages   TEXT[] NOT NULL DEFAULT '{python,javascript,typescript,go,java}',
  starter_code        JSONB NOT NULL DEFAULT '{}',     -- {language: code_template}
  test_cases          JSONB NOT NULL DEFAULT '[]',     -- [{input, expected_output, hidden}]
  time_limit_minutes  INTEGER NOT NULL DEFAULT 45,
  tags                TEXT[] NOT NULL DEFAULT '{}',
  archived_at         TIMESTAMPTZ,
  inserted_at         TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at          TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_coding_challenges_company_id ON coding_challenges (company_id);
CREATE INDEX idx_coding_challenges_job_id ON coding_challenges (job_id);
```

### `ai_scores`

The output of the AI scoring pipeline for a given interview session.

```sql
CREATE TABLE ai_scores (
  id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  application_id      UUID NOT NULL REFERENCES applications(id),
  video_session_id    UUID REFERENCES video_sessions(id),
  scored_by           VARCHAR(100) NOT NULL DEFAULT 'vertex_ai_gemini_1_5_pro',
  model_version       VARCHAR(100),
  composite_score     NUMERIC(4,2) NOT NULL,            -- weighted average 0.00–10.00
  breakdown           JSONB NOT NULL,
  -- Example breakdown structure:
  -- {
  --   "technical_depth":  {"score": 8.5, "weight": 0.35, "rationale": "..."},
  --   "communication":    {"score": 7.0, "weight": 0.25, "rationale": "..."},
  --   "problem_solving":  {"score": 9.0, "weight": 0.20, "rationale": "..."},
  --   "culture_fit":      {"score": 7.5, "weight": 0.10, "rationale": "..."},
  --   "role_fit":         {"score": 8.0, "weight": 0.10, "rationale": "..."}
  -- }
  strengths           TEXT[],
  areas_for_growth    TEXT[],
  recommended_action  VARCHAR(50),                      -- advance | reject | hold
  confidence          NUMERIC(4,3),                     -- 0.000–1.000 model confidence
  prompt_version      VARCHAR(50),                      -- for prompt regression tracking
  raw_response        TEXT,                             -- raw LLM output for audit
  processing_ms       INTEGER,
  status              VARCHAR(50) NOT NULL DEFAULT 'completed',
                      -- pending | completed | failed | overridden
  overridden_by_id    UUID REFERENCES users(id),
  inserted_at         TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),

  UNIQUE (application_id, video_session_id)
);

CREATE INDEX idx_ai_scores_application_id ON ai_scores (application_id);
CREATE INDEX idx_ai_scores_composite ON ai_scores (composite_score DESC);
```

### `audit_logs`

Immutable record of all significant state transitions. Written via application-level code (not DB triggers) to capture actor identity and request context.

```sql
CREATE TABLE audit_logs (
  id                  UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  company_id          UUID NOT NULL REFERENCES companies(id),
  actor_id            UUID REFERENCES users(id),       -- NULL for system actions
  resource_type       VARCHAR(100) NOT NULL,           -- "application", "ai_score", etc.
  resource_id         UUID NOT NULL,
  action              VARCHAR(100) NOT NULL,           -- "stage_changed", "score_overridden"
  previous_state      JSONB,
  next_state          JSONB,
  metadata            JSONB NOT NULL DEFAULT '{}',
  ip_address          INET,
  user_agent          TEXT,
  inserted_at         TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_audit_logs_company_id ON audit_logs (company_id);
CREATE INDEX idx_audit_logs_resource ON audit_logs (resource_type, resource_id);
CREATE INDEX idx_audit_logs_actor ON audit_logs (actor_id);
CREATE INDEX idx_audit_logs_inserted_at ON audit_logs (inserted_at DESC);
```

## Relationship Summary

```
companies (1) ──< (N) users
companies (1) ──< (N) jobs
companies (1) ──< (N) candidates
companies (1) ──< (N) coding_challenges

jobs (1) ──< (N) applications
jobs (1) ──< (N) coding_challenges

candidates (1) ──< (N) applications

applications (1) ──< (N) interviews
applications (1) ──< (N) ai_scores

interviews (1) ──< (N) video_sessions
interviews (N) >──< (N) users  [via interview_interviewers]
```

## Open Questions

1. **Multi-session scoring:** Should `ai_scores` represent one score per session, or one score per application (aggregated across all sessions)? Current design: one per session, plus Phoenix recomputes `applications.composite_score` on each new score via weighted average. This allows scoring evolution without losing history.

2. **Coding submission storage:** Where do we store submitted code? Options: (a) column on `video_sessions`, (b) separate `coding_submissions` table, (c) Cloud Storage + URL reference. Leaning toward a `coding_submissions` table for structured querying. Deferred to a follow-up RFC.

3. **Candidate deduplication:** A candidate applying to two different jobs at the same company creates two separate `applications` but one `candidates` row (unique on `company_id + email`). Cross-company deduplication is explicitly out of scope (privacy).
